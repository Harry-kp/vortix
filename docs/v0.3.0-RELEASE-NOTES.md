# Vortix v0.3.0 — what's new

**v0.3.0 is the architectural migration v1 ship.** Upgrade is automatic; existing
profiles, CLI commands, and killswitch state all keep working unchanged.

## Highlights

- **Engine FSM + session journal.** A typed connection state machine replaces the
  scattered status flags. Every session writes a JSONL event log to
  `${XDG_DATA_HOME}/vortix/sessions/*.jsonl` with 30-day / 30-file retention.
  Surfaces via `vortix journal {path,tail}`.
- **Layered secret store.** Optional encrypted store backed by the OS keyring
  (Keychain on macOS, Secret Service on Linux) with an AES-256-GCM + argon2id
  on-disk fallback. Manage entries with `vortix secrets {set,get,delete}`.
  Existing `.auth` files keep working — the store is opt-in.
- **Six new additive CLI subcommands.** `vortix engine`, `vortix journal`,
  `vortix settings`, `vortix secrets`, `vortix migrate`, `vortix export`. The
  pre-v0.3 commands (`up`, `down`, `status`, `list`, `import`, `killswitch`,
  …) are unchanged. See the README's "New in v0.3.0" subsection.
- **Hardened startup.** Defense-in-depth on the profile sidecar migration
  (`VORTIX_SKIP_MIGRATION=1` escape hatch), warn-only orphan-daemon scan when
  a previous run left `wg-quick` / `openvpn` behind, and a CI ceiling on
  `vortix --version` cold-start time so future changes can't inflate it
  silently.
- **Cargo workspace + 12 internal crates.** The codebase is now a flat
  matklad-style workspace with capability ports (Tunnel, Killswitch, DNS,
  Interface, NetworkStats, RouteTable, CommandRunner) in `vortix-core` and
  per-OS / per-protocol impls behind them. Adding new protocols or platforms
  is now mechanical. See [architecture-migration-v1.md](architecture-migration-v1.md).
- **JSON output carries `schema_version`.** Every `--json` envelope now begins
  with `"schema_version": 1`. The contract is versioned from day one;
  consumers can detect breaking changes instead of finding them at runtime.

## What's automatic

- **Profile sidecar backfill.** A `<name>.meta.toml` appears next to each
  existing `.conf` / `.ovpn` at first launch. Idempotent — re-runs are
  no-ops. v0.2.x ignores these files, so rollback is safe.
- **Existing CLI commands.** `vortix up`, `down`, `status`, `list`, `import`,
  `killswitch`, `delete`, `rename`, `reconnect`, `show`, `info`, `update`,
  `report`, `completions` all behave exactly as before.
- **Killswitch state.** Pf / iptables / nftables rules persist across the
  binary upgrade. Active VPN sessions also survive the upgrade — vortix
  doesn't supervise its spawned `wg-quick` / `openvpn` daemons.

## What's opt-in

- **Encrypted secret store.** Empty by default. Move OpenVPN credentials
  into it with `echo -n 'user:pass' | vortix secrets set creds/<profile>`.
  See [MIGRATION.md](MIGRATION.md#encrypted-secret-store-opt-in).
- **`settings.toml`.** Figment-layered (defaults → system → user → env).
  You don't need to create one; the runtime defaults match v0.2.x behavior.
  Inspect the resolved stack with `vortix settings`.
- **Session journal on-disk persistence.** Default on. To disable
  disk persistence, add `[journal] disk = false` to `settings.toml` — the
  live event bus still works.

## What's NOT in v0.3.0

- **No Windows binary.** A `vortix-platform-windows` stub crate compiles on
  Windows but every port returns `PlatformUnsupported`. Issue [#17](https://github.com/Harry-kp/vortix/issues/17).
- **No daemon mode.** `vortix daemon` doesn't exist yet — see plan 010.
  Issue [#16](https://github.com/Harry-kp/vortix/issues/16).
- **No lifecycle hooks.** Pre/post connect scripts aren't shipping in
  v0.3.0 — see plan 009. Issue [#36](https://github.com/Harry-kp/vortix/issues/36).
- **No "run without sudo."** Privilege separation depends on the IPC layer;
  see plan 011. Issue [#153](https://github.com/Harry-kp/vortix/issues/153).

## For maintainers and contributors

The bundle is six coordinated plans (`docs/plans/2026-05-24-001-*` through
`-006-*`), the rollout playbook (`-007-*`), and the architectural-completion
quick wins (`-008-*`). The deferred multi-week subsystems are documented as
plans 009–013 — pick one up when its motivating feature lands.

Full surface map: [architecture-migration-v1.md](architecture-migration-v1.md).

## Upgrade and rollback

Read [MIGRATION.md](MIGRATION.md) for upgrade instructions. Rollback in one
command:

```sh
cargo install vortix --version 0.2.2 --force
```

Migration artifacts (`.meta.toml` sidecars, `secrets.enc`, `sessions/*.jsonl`)
are inert to v0.2.x.

## Got questions?

Read the [FAQ](v0.3.0-FAQ.md) first — six common questions are answered there.
Linux-specific issues go in [discussion #184](https://github.com/Harry-kp/vortix/discussions/184).
Everything else: open an issue. `vortix bug-report` attaches the current
session's journal so the report carries useful context out of the box.
